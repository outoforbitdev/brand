# brand

[![Test](https://github.com/outoforbitdev/brand/actions/workflows/test.yml/badge.svg?branch=main)](https://github.com/outoforbitdev/brand/actions/workflows/test.yml)

Shared brand assets (logos, icons, favicons) for the outoforbitdev organization.

SVG files in `src/` are the only source of truth. Every published file is generated by CI and deployed to GitHub Pages. Generated files are never committed.

**This site is public.** Never put confidential assets in this repo.

## URL scheme

```
/v1/<static|dynamic>/<asset>[-<W>x<H>].<ext>
```

Examples, on `https://brand.<domain>` (a placeholder until the domain is final):

- `/v1/static/ood_logo.svg`
- `/v1/static/ood_logo-24x24.png`
- `/v1/dynamic/ood_logo_seasonal.svg`
- `/v1/dynamic/ood_logo_seasonal-24x24.png`

Naming rules:

- Lowercase only. Asset names are snake_case and use underscores, never hyphens.
- A hyphen appears only before the size.
- SVG files have no size suffix.
- PNG sizes are square pixel dimensions, written `<size>x<size>`, such as `24x24`.
- The extension is always in the file name so Pages sends the correct Content-Type.
- URLs are flat, so asset names must be unique across the repo. Source files may still be grouped under `src/<asset_group>/`.

The generated index page at the site root lists every published file with a preview. `/v1/manifest.json` lists every published path as `{ "paths": [...] }`.

### Static and dynamic

- **static**: the bytes never change once published. Seasonal variants are separate static assets.
- **dynamic**: a stable alias whose content may change. A dynamic alias serves the static variant whose window contains today's UTC date, or its default otherwise.

### Stability

`v1` is unstable until this README says otherwise. After that, breaking changes go under `/v2/`.

Paths are a public API. Never rename or remove a published path. Other projects depend on them.

## Consuming assets

Either copy a file into your project, or fetch it by URL.

- Prefer copying a `static` file when you need a guaranteed result, since it never changes.
- Use a `dynamic` URL when you want the current seasonal variant without doing anything.

GitHub Pages caches for roughly 10 minutes and allows no custom headers, so a seasonal swap or a fresh deploy is not instant.

## Development

Requires the Node version in `.nvmrc`. Install dependencies with `npm ci`. Commands run through `just`.

| Command | What it does |
| --- | --- |
| `just build` | Builds everything into `dist/` and records new static checksums. |
| `just build-check` | Same build in `--check` mode. Never writes `static-checksums.json`. This is what CI runs. |
| `just test` | Runs the unit tests (`node --test`). |
| `just lint` | Runs ESLint. |

`just build` forwards extra arguments to `node scripts/build.js`:

| Flag | Effect |
| --- | --- |
| `--check` | Never writes `static-checksums.json`. A static file missing from it, or with a changed hash, is an error. |
| `--allow-static-change` | Permits changed hashes for existing static files and rewrites those entries. Ignored with `--check`. Never use it in CI. |
| `--date YYYY-MM-DD` | Evaluates the seasonal schedule as if it were that UTC date. |
| `--variant <name>` | Forces every dynamic alias that lists the static asset `<name>` (as default or scheduled variant) to use it. It is an error if `<name>` is not a static asset or no alias uses it. |

For example: `just build --date 2026-12-25`. Once a dynamic alias exists, `just build --variant <name>` previews a static asset that the alias uses.

### Source requirements

- Sources must be square. The build rejects any SVG whose `viewBox` is not square.
- Convert text to paths. The PNG renderer has limited font handling.
- Inkscape files are fine. The build simplifies them with svgo (Inkscape and Sodipodi data, metadata, comments and unused ids are stripped, the `viewBox` is kept, fixed `width` and `height` are dropped), then renders both the original and the simplified SVG and fails if the pixels differ.

### Add an asset

1. Add the SVG under `src/<asset_group>/<asset_name>.svg`.
2. Add an entry to `assets.json`:

   ```json
   {
     "name": "my_icon",
     "source": "src/my_icon/my_icon.svg",
     "formats": ["svg", "png"],
     "sizes": [16, 32, 64]
   }
   ```

3. Run `just build`.
4. Commit the SVG, `assets.json` and the updated `static-checksums.json`.

### Add a seasonal variant

1. Add the variant as its own static asset, as above (for example `ood_logo_christmas`).
2. Add or extend a dynamic alias in `assets.json`:

   ```json
   "dynamic": [
     {
       "name": "ood_logo_seasonal",
       "default": "ood_logo",
       "schedule": [
         { "variant": "ood_logo_christmas", "from": "12-01", "to": "12-31" }
       ]
     }
   ]
   ```

3. Run `just build`, then preview with `just build --date 2026-12-15` and `just build --variant ood_logo_christmas`.
4. Commit `assets.json` and `static-checksums.json`.

Rules:

- Every variant of an alias, including the default, must have identical formats and sizes. This keeps alias URLs from disappearing when the season changes.
- Windows are inclusive `MM-DD` ranges evaluated against the UTC date. They may wrap around the new year, such as `12-15` to `01-05`.
- Overlapping windows in one alias are an error.
- An alias can only reference static assets.

### Static immutability

Published static files must never change. `static-checksums.json` records the hash of every published static file, along with the resvg and svgo versions used.

- A new static file is added to the checksum file by `just build`. Commit it.
- A changed hash fails the build. If the tool versions also changed, the error names a resvg or svgo upgrade as the likely cause.
- A removed static path always fails the build.
- If a change to a static file is truly intended, run `just build --allow-static-change` locally and commit the rewritten checksums. Consumers who rely on the old bytes will see them change, so avoid this. Prefer adding a new asset.

CI runs `just build-check`, which never writes and fails on any mismatch.

## Deployment

The `Deploy` workflow builds and deploys to GitHub Pages on a push to `main`, daily at 00:17 UTC, and on manual dispatch. Manual dispatch accepts an optional `variant` input to force a seasonal variant. Dispatches from other branches only validate the build and do not deploy.

The scheduled run deploys whatever is on `main`. If a scheduled run fails, the previous deploy stays live.

Pull requests, pushes to `main` and manual runs use the `test` workflow: tests, lint and `just build-check`.

### Keeping the daily schedule alive

GitHub disables scheduled workflows in public repositories after 60 days without repository activity. A push to `main` counts as activity. If the seasonal swap stops, re-enable the `Deploy` workflow under the Actions tab. A keepalive job was deliberately not added because it cannot work once the schedule is disabled.

## Setup (manual steps)

These steps happen in GitHub and DNS, outside the code.

1. In Settings, Pages, set the source to GitHub Actions.
2. In Settings, Environments, open `github-pages` and restrict deployment branches to `main`.
3. Recommended: protect `main` with a branch protection rule that requires pull requests and requires the `test` check to pass. The scheduled deploy publishes whatever is on `main`.
4. Add a DNS `CNAME` record from `brand.<domain>` to the organization's Pages host, `outoforbitdev.github.io`.
5. Set the custom domain in Settings, Pages, and enforce HTTPS once the certificate is issued. A `CNAME` file in the repo is ignored by Actions deploys.
6. Verify the domain at the organization level, so it cannot be taken over. Add the TXT record `_github-pages-challenge-outoforbitdev` with the value GitHub shows.
7. Verify a static asset, a dynamic asset and a manual run with a forced variant on the live domain.

The final domain name (`brand.` or `branding.`) is undecided.

### Cloudflare notes

- Start with the record DNS-only (grey cloud) so GitHub can issue its certificate and enforce HTTPS.
- If you have CAA records, make sure they allow `letsencrypt.org`.
- If you proxy afterwards, use SSL mode Full (strict), never Flexible.
- Proxying lets you add Cache Rules to work around the roughly 10 minute Pages cache, for example a long TTL on `/v1/static/*` and a short TTL on `/v1/dynamic/*`.
