# Brand assets repo: URL scheme, layout, and build/deploy pipeline

Issue: https://github.com/outoforbitdev/brand/issues/1

## Intent

The outoforbitdev org needs one place for shared brand assets (logos, icons, favicons). Other apps either copy files into their own source or fetch them live by URL. The repo is hosted on GitHub Pages at a custom domain (`brand.<domain>`, placeholder until the domain is final). SVG files in `src/` are the only source of truth. All published files are generated by CI.

## Goals

- Stable, public, versioned URLs for every asset.
- Adding an asset or size requires only a manifest change plus the SVG.
- Published static files are immutable. A changed static file fails CI.
- A dynamic alias (such as the seasonal logo) serves the right variant for the current UTC date.
- Published SVGs are simplified, with no editor data.

## Non-goals

- `.ico` favicons (tracked in issue #2).
- `@2x` size variants.
- Cache control headers or a CDN (Cloudflare can be added later).
- Confidential assets. The site is public.

## Anti-goals

- Renaming or removing a published path.
- Committing generated PNGs or SVGs.
- Hashes that drift because of renderer or optimizer upgrades without anyone noticing.

## URL scheme

```
/v1/<static|dynamic>/<asset>[-<W>x<H>].<ext>
```

Examples: `/v1/static/ood_logo-24x24.png`, `/v1/static/ood_logo.svg`, `/v1/dynamic/ood_logo_seasonal.svg`, `/v1/dynamic/ood_logo_seasonal-24x24.png`.

Rules:

- Lowercase only. Asset names use underscores, never hyphens. A hyphen appears only before the size.
- Size is omitted for SVG.
- Sizes are pixel dimensions. The manifest lists one integer per size, which is the width. The height follows the aspect ratio, rounded to a whole pixel, and the filename carries both (`WxH`).
- The extension is always in the filename so Pages sends the correct Content-Type.
- **static**: bytes never change once published. Variants are separate static assets.
- **dynamic**: a stable alias whose content may change.
- **Flat URLs** (decided): no per-asset folder in the URL, so asset names must be unique across the repo. Source files may still be grouped under `src/<asset_group>/`. If grouping is ever needed, it goes in `/v2/`.
- `v1` is unstable until the README says otherwise. After that, breaking changes go under `/v2/`.
- Paths are a public API.

## Repo layout

```
.
├── src/<asset_group>/<asset>.svg    # SVG sources of truth (may be Inkscape files)
├── assets.json                      # manifest
├── static-checksums.json            # hashes of published static files
├── scripts/                         # Node build scripts
├── .github/workflows/deploy.yml
├── Justfile
├── dist/                            # generated, gitignored
└── README.md
```

The existing flat `src/ood_logo.svg` moves to `src/ood_logo/ood_logo.svg` to match the layout.

## Manifest (`assets.json`)

```json
{
  "assets": [
    { "name": "ood_logo", "source": "src/ood_logo/ood_logo.svg", "formats": ["svg", "png"], "sizes": [16, 24, 32, 64, 128, 256, 512] },
    { "name": "ood_logo_christmas", "source": "src/ood_logo/ood_logo_christmas.svg", "formats": ["svg", "png"], "sizes": [24, 64, 256] }
  ],
  "dynamic": [
    {
      "name": "ood_logo_seasonal",
      "default": "ood_logo",
      "schedule": [ { "variant": "ood_logo_christmas", "from": "12-01", "to": "12-31" } ]
    }
  ]
}
```

A dynamic alias can only reference a static asset. Its output formats and sizes are those of the chosen variant. Windows are inclusive `MM-DD` ranges evaluated against the UTC date. The initial windows are a placeholder, and the Christmas window above is only an example.

## Build pipeline

Runtime: Node (current LTS on CI). Commands run through `just`. Tooling is decided as follows:

- **PNG rendering:** `@resvg/resvg-js`, rendering at an exact pixel width. Deterministic, with no system dependencies. Text in logos must be converted to paths in the source SVG, since resvg has limited font handling.
- **SVG output:** `svgo` with a config that strips Inkscape and Sodipodi data, metadata, comments and unused ids, and keeps the `viewBox`. The mm `width` and `height` are dropped so consumers can scale freely. Plain SVG sources pass through unchanged.
- **Safety check:** the build renders the original and the simplified SVG with resvg and fails if the pixels differ.

Steps:

1. Validate the manifest: naming rules, sources exist, no duplicate output paths, dynamic references resolve.
2. For each static asset, write the simplified SVG and render each PNG size into `dist/v1/static/`.
3. For each dynamic asset, choose the variant whose window contains today's UTC date, otherwise the default. Copy that variant's outputs to `dist/v1/dynamic/<alias>...`. A `--date` override (and the workflow input) forces a date or variant for testing.
4. **Static immutability check:** hash every file in `dist/v1/static/` and compare against `static-checksums.json`. New files are added to it. A changed existing file fails the build unless an explicit override is passed. The checksum file records the resvg and svgo versions. If hashes change and the versions changed too, the error says the upgrade is the likely cause.
5. Emit `dist/v1/manifest.json` (all published paths) and a generated `dist/index.html` listing every asset with a preview and URL.
6. Add `dist/.nojekyll`.

## Deploy workflow

- Triggers: push to `main`, a daily `schedule`, and `workflow_dispatch` (optional input to force a seasonal variant or date).
- Steps: checkout, set up Node, install, run the build, `actions/configure-pages`, `actions/upload-pages-artifact` (path `dist`), `actions/deploy-pages`.
- Permissions: `contents: read`, `pages: write`, `id-token: write`. Environment: `github-pages`.
- Pages deploys only from `main`. A pull request workflow runs the build and tests without deploying, so the immutability check fails CI on PRs.
- A keepalive step or reminder prevents GitHub from disabling the scheduled workflow after 60 days of inactivity.

## Testing

Unit tests for manifest validation, naming rules, variant selection by date (including window edges), checksum logic, and SVG simplification. An end-to-end test builds a fixture manifest and checks the output tree.

## Manual steps (outside the code)

- Enable Pages with source GitHub Actions.
- Add the DNS CNAME record, set the custom domain in Settings, and enforce HTTPS. A `CNAME` file in the repo is ignored by Actions deploys.
- Verify a static asset, a dynamic asset, and a forced-variant manual run on the live domain.

## Constraints

- Pages caches for about 10 minutes and allows no custom headers, so seasonal swaps are not instant.
- The published site is public.

## Approaches considered

- **PNG rendering:** `@resvg/resvg-js` (chosen), `sharp`/librsvg (rendering can differ across platforms and versions, which breaks hashing), Inkscape CLI (heavy install, slow, version drift). Chosen by the user.
- **SVG simplification:** SVGO in the build (chosen), or Inkscape "Plain SVG" export (still verbose, and a manual step contributors can forget). Chosen by the user.
- **URL shape:** flat (chosen by the user) or grouped by asset. A change would require `/v2/`.

## Additional calls (author's decisions, open to correction)

- **Checksum workflow:** `just build` writes new entries to `static-checksums.json` locally and the contributor commits the file. CI runs the build in `--check` mode, which never writes and needs only `contents: read`. A changed existing hash fails unless `--allow-static-change` is passed locally, which rewrites that entry. The override is never used in CI.
- **Reproducibility:** dependencies are exact-pinned and installed with `npm ci`, and Node is pinned via `.nvmrc`. Checksums should match across macOS and Linux. If a cross-platform mismatch shows up in testing, checksums for PNGs are generated in CI only, and the plan must say so.
- **Scheduled runs:** they run the same check. A failure fails loudly (GitHub notifies the repo owner) and the previous deploy stays live.
- **Source readiness:** `src/ood_logo.svg` is square (viewBox 88.95 x 88.95), has no `<text>`, filters or fonts, and moves to `src/ood_logo/ood_logo.svg`. `ood_logo_christmas` does not exist yet. The initial manifest contains only `ood_logo`, and the seasonal alias is added when the variant exists. Sources can be any shape. An earlier draft required square sources, which the issue never asked for.
- **Pixel-equality safety check:** compared at 512px with a small per-channel tolerance, to allow harmless path rounding.
- **Dynamic alias consistency:** the validator requires every variant of an alias, including the default, to have identical formats and sizes, and the build requires them to produce identical file names (the same aspect ratio). This keeps alias URLs from disappearing when the season changes.
- **Windows:** overlapping windows in one alias are a validation error. Wrap-around ranges (e.g. `12-15` to `01-05`) are supported. `02-29` is a valid bound.
- **Deploys:** the scheduled run deploys whatever is on `main`. Branch protection with required PR checks is recommended and noted in the README.
- **URLs:** the generated index and `manifest.json` use relative paths. No base URL setting is needed.
